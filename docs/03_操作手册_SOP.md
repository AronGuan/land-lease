# 国有土地租赁智能管理系统 · 操作手册（SOP）

> 版本 v1.0 ｜ 对应核算口径 v1.2 ｜ 核算基准日 2026-09-30
> 适用角色：经办人（复核/录入）、管理员（配置/审计）
>
> **本文是「界面级怎么点」的操作手册。** 若要交给本地人员执行、要看 3,000 份的人天测算与错漏兜底机制，
> 见 `06_作业SOP与测算.md`（对应赛题 表 4「流程与测算」20 分）。

## 一、系统定位一句话

把 3,000 份纸质合同扫描件变成「一宗一档台账 + 逐年应缴/实缴/欠缴 + 13 类问题清单 + 催缴与税务输出」，
**金额由纯规则引擎计算（AI 不参与算钱）**，AI 只负责把图片变成结构化字段，并明确标注每个字段的可信程度。

---

## 二、人机分工（务必理解，避免误判）

| 处理方式 | 系统含义 | 人的动作 | 时间成本 |
|---|---|---|---|
| **自动通过** | 关键字段全对 + 规则校验通过 + 置信度 ≥ 0.90 | 经办人**批量确认**（看摘要，不逐项对照原件） | 每份几秒 |
| **人工复核** | 涂改 / 冲突 / 低置信 / 存疑 | 逐项对照原件，可改可退回 | 每份 1–2 分钟 |

> ⚠️ 「自动通过」**不等于跳过人工**。批量确认前必须看二次确认弹窗中的「最低置信度 Top3 预警」。

---

## 三、三级识别（看懂颜色就能干活）

| 颜色 | 级别 | 含义 | 你要做什么 |
|---|---|---|---|
| 🟢 绿标 | L1 直接识别 | 页面清晰、校验通过 | 快速扫一眼，无需改动 |
| 🟡 黄底 | L2 反推 | 看不清但可由其他字段推出（如金额由大写推、终止日由起租日+年限推） | **对照原件确认推导结果** |
| 🔴 红底 | L3 不可识别 | 看不清且推不出 | **必须手工录入**，否则该项为空 |

**强制降级的四种情形**（系统会自动整份转人工复核）：
1. 字段有涂改（实测教训：LX-001 年租金真值 3,998.25，AI 首读给出 4,018.25，恰为涂改前内容）
2. 与登记 / 缴费数据冲突
3. 关键字段低置信
4. 进入「存疑待确认」

## 四、主链路 8 步操作

### 步骤 0 · 准备基础数据（一次性，管理员）

导入四张基础表：

| 数据 | 入口 | 说明 |
|---|---|---|
| 计租标准 + 土地级别范围 | 系统管理 → 计租标准 | 决定「随标准调整」型合同每年单价 |
| 不动产登记导出 | 后端导入（`scripts/seed.py` 或接口） | 提供登记面积、权利人、登记坐落 |
| 租金缴费记录 | 同上 | 实缴归集用 |
| 租金减免登记 | 系统管理 → 计租标准（底部） | 减免比例按年度区间生效 |

### 步骤 1 · 上传（人）

1. 进入 **合同治理 → 批次导入**
2. 点「新建批次」，选择批次类型（新签 / 续期 / 变更 / 现场补档）
3. 拖入扫描件，**文件命名规范：`档案号_页序.jpg`**
   - 例：`LX-001_1.jpg`、`LX-001_2.jpg` 会自动合成一份 3 页档案
4. 系统落盘到 `storage/{批次号}/{档案号}/{页序}.jpg` 并记录 SHA256

### 步骤 2–3 · 识别 + 判定（系统，无需人工）

点「执行识别」后，系统依次完成：
1. VLM 逐页抽取 27 个字段（默认主通道 `qwen3-vl-plus`；可在「系统管理 → 模型管理」切到开源通道 `Qwen/Qwen3-VL-32B-Instruct` 或本地 PaddleOCR，切换后立即生效不需要重启）
2. 多页合并（每字段取最高置信度）
3. 规则预校验：身份证校验位、电话 11 位、日期合法性、金额区间
4. 反推规则库补全：金额互推 / 日期互推 / 年限互推 / 大小写互推
5. 三级判定 + 强制降级

### 步骤 4 · 归宗比对（系统）

- 旧地号 ↔ 单元号位段换算：`09-05-0106` ↔ `000000009005GB00106F00089385`（第 7-9 / 10-12 / 15-19 位，前导零可省）
- 归宗打分：原合同编号 +60 / 宗地号 +30 / 证件号 +15 / 面积 +10 / 坐落 +10 / 日期接续 +10，**≥40 分归同一宗**
- 与登记、缴费比对 → 生成 13 类问题清单

### 步骤 5 · 复核（人，核心环节）

进入 **合同治理 → 复核工作台**：

1. 顶部筛选「待复核」或「人工复核档」
2. 左侧列表点选档案 → 右侧显示 27 个字段
3. **逐项核对**：所有字段都可直接改（输入框），回车或点笔图标保存 → 自动留痕到审计日志
4. 改完点「确认此份」

**批量确认（自动通过档）**：
1. 勾选多份 → 点「批量确认」
2. 弹窗核对：份数 / 涉及批次 / 含人工复核档数 / 校验通过率 / **最低置信度 Top3 预警**
3. 确认无误 → 「确认通过」；有疑虑 → 「再看看」

### 步骤 6 · 核算（系统）

按口径逐宗逐年计算：分段计租 → 月度折算（起租/终止当月均计入）→ 减免乘算 → 实缴归集 → 欠缴。
每条核算落 `rent_calc_trace`（输入快照 + 公式 + 口径版本），**任何数字都可追到来源**。

### 步骤 7 · 查看与输出（人）

| 需求 | 入口 |
|---|---|
| 一宗一档全貌（合同链 + 逐年应缴 + 缴费归集 + 减免） | 宗地台账 → 点宗地键下钻 |
| 谁欠多少、欠哪几年 | 收缴管理 → 欠缴看板 |
| 数据质量问题 | 合同治理 → 问题清单（13 类） |
| 到期提醒 | 收缴管理 → 到期日历 |
| 催缴通知 | 欠缴看板 → 勾选 → 生成催缴通知书（短信为模拟） |
| 税务推送 | 统计报表 → 税务推送 |

### 步骤 8 · 增量回路

新合同 / 续期 / 变更 / 现场补档 → 新建批次 → 识别 → 归宗 → **只重算该宗应缴与欠缴** → 台账/清单/催缴对象同步更新（不重跑全量）。

## 五、常见问题处置

### 5.1 面积与登记不一致

系统按口径四(三) 暂按**合同面积**计算，并记问题清单「面积与登记不一致」。
若该宗被判「存疑待确认」，按第十二条**取对产权人有利（应缴较少）的算法暂算**，差额记入问题清单。

### 5.2 大小写金额不一致

按口径四(一) **暂按大写**，记「年租金大小写不一致」。复核时以原件为准修正。

### 5.3 同一宗地两份合同期间重叠

系统按问题清单结论：**旧合同自新合同起始日前终止**计收（重叠段只算新合同）。
该条已判为「存疑待确认」，问题清单同时给出与「以旧合同为准」算法的差额。

### 5.4 合同到期未续

系统按口径五：**按最后一份合同继续计收至 2026-12-31**，并记「合同到期未续」。
建议在到期日历中提前 30 天启动续签。

### 5.5 存疑待确认怎么处理

1. 问题清单中找到该条（会写明存疑之处、暂按算法、与另一算法差额）
2. 报主管部门**书面确认**
3. 确认后按确认算法重算，点「消解」关闭问题并留痕

## 六、操作红线（做错会被审计日志抓到）

1. **不得跳过二次确认**直接批量通过
2. **不得修改已确认档案而不留痕**（改字段必须走复核工作台的输入框，系统自动记前后值）
3. **不得手工改数据库金额**（金额只能由核算引擎产生，改数据必须改输入再重算）
4. 撤回批次会**整体回滚并级联重算**，确认前先看批次号
