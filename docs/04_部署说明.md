## 零、离线部署包（推荐，10 分钟装完）

正式交付形态是**一个 zip**，装在主管部门提供的服务器上，**安装过程不从外网下载组件**。
包内自带编译好的前端与全部运维脚本，目标机只需 Python 与 MySQL。

### 1. 部署包内容

```
国有土地租赁智能管理系统_v1.0_离线部署包_YYYYMMDD.zip
├─ 安装.bat / install.sh      一键安装（建虚拟环境 → 装依赖 → 生成 .env）
├─ 启动.bat / start.sh        启动服务（单端口 8000，自动打开浏览器）
├─ 停止.bat / stop.sh
├─ 备份.bat / backup.sh       备份数据库 + 合同原件到 backup/时间戳/
├─ 恢复.bat / restore.sh      从备份恢复（二次确认）
├─ 查看日志.bat / logs.sh
├─ .env.example               配置模板（密钥只填在这里）
├─ requirements.txt
├─ wheels/                    离线依赖（--with-wheels 打包时包含）
├─ landlease/                 后端源码（识别 / 归宗 / 核算 / 催缴）
├─ web/                       前端构建产物（后端直接托管，无需 nginx / Node）
├─ scripts/                   seed、一键预检、导入导出等运维脚本
├─ docs/                      数据模型、PRD、SOP、本说明
└─ schema.sql                 27 张表结构（也可由应用启动时自动建）
```

### 2. 安装步骤（Windows）

1. 解压到任意目录（路径不要含中文与空格以外的特殊字符）
2. 双击 **`安装.bat`** —— 自动建 `.venv`、装依赖、生成 `.env` 并打开供填写
3. 填写 `.env`：`DB_PASSWORD`、识别通道的 API Key（其余保持默认）
4. 确认 MySQL 已启动，执行 `CREATE DATABASE landlease DEFAULT CHARSET utf8mb4;`
5. 双击 **`启动.bat`** —— 浏览器自动打开 `http://127.0.0.1:8000`
6. 首次启动自动建 27 张表；如需演示数据，执行 `scripts/seed.py`

> 目标机无外网时：打包方先在有网机器执行 `python scripts/build_release.py --with-wheels`，
> 生成的 `wheels/` 会随包带走，安装脚本自动改用
> `pip install --no-index --find-links=wheels` 离线安装。

### 3. Linux

```bash
unzip 国有土地租赁智能管理系统_v1.0_离线部署包_*.zip && cd 国有土地租赁智能管理系统_v1.0_离线部署包_*
./install.sh      # 建 venv + 装依赖 + 生成 .env
vi .env           # 填 DB_PASSWORD 与 API Key
./start.sh        # 后台启动，日志写 logs/backend.log
./stop.sh   ./backup.sh   ./restore.sh   ./logs.sh
```

## 二、本地部署（推荐用于比赛现场）

### 1. 准备配置

```bash
cp .env.example .env
# 编辑 .env：填 DB_PASSWORD、DASHSCOPE_API_KEY、OPENSOURCE_API_KEY
```

`.env` 必须包含：

```ini
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=***
DB_NAME=landlease
# 闭源云端通道
DASHSCOPE_API_KEY=sk-***
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DEFAULT_VL_MODEL=qwen3-vl-plus
# 开源可部署通道（详见第七章「模型通道与现场切换」）
OPENSOURCE_BASE_URL=https://api.siliconflow.cn/v1
OPENSOURCE_API_KEY=sk-***
OPENSOURCE_VL_MODEL=Qwen/Qwen3-VL-32B-Instruct
AUTO_PASS_CONFIDENCE=0.90
CALC_RULE_VERSION=v1.2
```

> 💡 任何一项 `*_API_KEY` 缺失都不影响系统启动，只影响对应通道的可用性：缺 KEY 的通道在「模型管理」页显示灰色不可用，其余通道照常工作。

> 🔒 `.env` 已在 `.gitignore` 中；代码内不硬编码任何密钥。

### 2. 建库

```sql
CREATE DATABASE landlease DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

表结构由应用启动时自动创建（27 张表）；如需手工执行见 `docs/schema.sql`。

### 3. 装后端依赖

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt      # Windows
# .venv/bin/pip install -r requirements.txt        # macOS / Linux
```

### 4. 灌入基础数据（演示用练习集）

```bash
.venv/Scripts/python scripts/seed.py --clear --force
```

预期输出：`合同 50，宗地 30，应缴 618，缴费 413，问题 72`

### 5. 启动后端

```bash
.venv/Scripts/python -m uvicorn landlease.app.main:app --host 127.0.0.1 --port 8000
```

自检：`curl http://127.0.0.1:8000/api/health`
应返回 `{"status":"ok","database":"ok","table_count":27,...}`

### 6. 启动前端

```bash
cd frontend
npm install
npm run dev        # http://127.0.0.1:5173
```

开发期 `vite.config.ts` 已配置 `/api` 代理到 `127.0.0.1:8000`；
若后端端口不同，改 `vite.config.ts` 的 `server.proxy['/api'].target`。

### 7. 一键自检（部署后必跑）

```bash
python scripts/smoke_api.py                       # 28 项接口冒烟
python scripts/verify_calc.py                     # 练习集核算 30/30 + 618/618
python scripts/verify_test20.py                   # 盲测 4/4 + 92/92
python landlease/tests/test_calc.py               # 核算单测 10 项
python landlease/tests/test_recognize.py          # 识别单测 9 项
python landlease/tests/test_grouping.py           # 归宗单测 7 项
```

## 三、Docker 部署（一键起三件套）

```bash
cp .env.example .env    # 填 DASHSCOPE_API_KEY；DB_PASSWORD 可留空用默认
docker compose up -d --build
```

访问 `http://localhost`（Nginx 反代 `/api` 到后端，同域无 CORS）。

初始化数据：

```bash
docker compose exec backend python scripts/seed.py --clear --force
```

| 服务 | 端口 | 说明 |
|---|---|---|
| frontend | 80 | Nginx + 静态资源 + /api 反代 |
| backend | 8000 | FastAPI + 核算引擎 |
| db | 3306 | MySQL 8.0（数据卷 `db_data`） |

备份：

```bash
docker compose exec db mysqldump -uroot -p"$DB_PASSWORD" landlease > backup/landlease_$(date +%F).sql
```

## 五、常见排障

| 现象 | 原因 | 处理 |
|---|---|---|
| `/api/health` 返回 `degraded` | 数据库连不上 | 检查 `.env` 的 DB_* 与 MySQL 是否启动 |
| 识别全部失败 | `DASHSCOPE_API_KEY` 未配 / 网络不通 | 查 `/api/health` 的 `api_key_configured`；确认可访问 dashscope |
| 前端页面 502 | 后端未启动或端口不符 | 核对 `vite.config.ts` 代理 target |
| 前端 `127.0.0.1` 打不开但 `localhost` 可以 | Vite 只监听 IPv6 | 已固定 `server.host = '127.0.0.1'` |
| 接口 500 且日志为 Pydantic 序列化错误 | 端点裸返回 ORM 对象 | 用 `_common.orm_to_dict()` 转换 |
| 上传大文件失败 | Nginx 默认 1M | 已设 `client_max_body_size 100m` |
| 核算金额与标准答案差 0.01 | 舍入口径不一致 | 确认走 `calc.round2()`（float64 链 + Python round） |

## 七、模型通道与现场切换

> 对应赛题第五节(2)「模型调用要做成可配置、可切换；正式环境使用政务网内的模型服务或在本地服务器部署的开源模型」
> 与表 4「部署与运行——模型能否现场切换」。

### 1. 三条通道

| 通道 | 类型 | 服务地址 | 模型名 | 用途 |
|---|---|---|---|---|
| qwen3-vl-plus | 闭源云端 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3-vl-plus` | 默认主通道，通用识别抽取 |
| Qwen3-VL-32B（开源） | **开源可部署** | `https://api.siliconflow.cn/v1`（可在界面改） | `Qwen/Qwen3-VL-32B-Instruct` | 权重开源（Apache-2.0），现场切换演示用 |
| PaddleOCR（本地） | 本地离线 | — | `paddleocr` | CPU 部署，政务网/离线降级兜底 |

通道元数据落 `model_config` 表；**凭据只存环境变量名**（`params.api_key_env`），明文 Key 一律走
`.env`，不进数据库、不进请求体。缺失凭证的通道在界面显示「未配置 <变量名>」，其余通道照常可用。

### 2. 现场切换（演示动作）

1. 打开 **系统管理 → 模型管理**；
2. 目标通道点 **「设为主通道」** —— 只改 `model_config.is_active` 并写一条
   `audit_log(action=model_switch)`（记录切换前后通道名、模型、地址），**下一份文档立即生效，不重启服务**；
3. 点 **「测试连通」** 发一个 1-token 请求，验证「地址可达 + 鉴权通过 + 模型名存在」，不耗实质额度；
4. **「编辑」** 可改通道名称、模型名、服务地址、凭据环境变量名，用于把开源通道从托管商切到政务网内服务。

识别调用链：`channel.resolve()` 解析当前主通道 → `vlm.extract_page(base_url, api_key, model)`
→ `recognize.recognize_document(channel=...)`。批次识别在任务开始时锁定通道并写
`audit_log(action=ocr_channel)`，保证一批文档同通道可追溯。

> ⚠️ 改完 `.env` 中的地址或密钥**必须重启后端**（`.env` 在启动时加载）；仅切换主通道不需要重启。

### 3. 正式环境：把开源通道换成自建服务

```bash
# 1× A100/H100 80G 起服务（32B；FP8/AWQ 量化可降到 48G）
pip install -U "vllm>=0.11.0"
vllm serve Qwen/Qwen3-VL-32B-Instruct \
  --served-model-name Qwen/Qwen3-VL-32B-Instruct \
  --host 0.0.0.0 --port 8000

# 系统内把开源通道地址改成内网服务（界面「编辑」或改 .env 后重启）
OPENSOURCE_BASE_URL=http://10.0.0.20:8000/v1
```

> 权重来源：HuggingFace / ModelScope `Qwen/Qwen3-VL-32B-Instruct`（Apache-2.0），
> 离线部署时先把权重下载到内网镜像，部署包不从外网拉取组件。

| qwen3-vl-plus（闭源） | 练习集 50 份 | 0.96 | ≈7.5s | 主通道基线 |
