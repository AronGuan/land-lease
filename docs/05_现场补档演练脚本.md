# 现场补档 · 20 分钟演练脚本

> 用途：比赛现场演示「评委指定一份合同撤回并重导」全链路。
> 总预算 20 分钟，含缓冲。每段标注**预算时间 / 说什么 / 点什么 / 看什么**。

---

## 0 · 开场（1 分钟）

| 项 | 内容 |
|---|---|
| 说什么 | 「这道题的核心不是把图片转成文字，而是**三千份纸，最后要变成能算钱、能追责、能催缴的一本账**。系统里 AI 只负责读字段，**金额一分钱都由规则引擎算**，每个数字都能追到来源。今天我不讲 PPT，直接从一份合同开始，现场走完补档全流程。」 |
| 点什么 | 打开 `http://127.0.0.1:5173` → 工作台 |
| 看什么 | 六张 KPI 卡（26 宗地 / 累计应缴 ¥403,377.79 / 累计欠缴 ¥108,600.93 / 待复核 11 份 / 待处理问题 61 条）+ 欠缴 Top5 |

**一句话价值锚点**：「这 30 宗、618 条年度应缴，和标准答案逐条对过——**汇总级 30/30、年度级 618/618 全对**。盲测另外抽了 20% 没见过的档案，也是 4/4 宗地、92/92 年度全对。」

---

## 1 · 领材料 + 上传（2 分钟）

| 项 | 内容 |
|---|---|
| 说什么 | 「现场补档的第一个动作是建批次。**导入即建批次**，后面万一要撤回，整批一起回滚，不会留下半截数据。」 |
| 点什么 | 合同治理 → 批次导入 → 新建批次（类型选「现场补档」）→ 拖入 `LX-001_1.jpg`、`LX-001_2.jpg`、`LX-001_3.jpg` |
| 看什么 | 批次列表出现新批次，`文件数=3`、`档案数=1`（三页自动合成一份） |

**要点提示**：「文件名就是档案号 + 页序，三页自动归为一份合同，不用手工分组。」

---

## 2 · 识别 + 归宗 + 重算（3 分钟）

| 项 | 内容 |
|---|---|
| 说什么 | 「点执行识别。这里做四件事：逐页抽字段、多页合并、规则校验、反推补全。**关键是我把识别分成了三级**，不是笼统给个『准确率』。」 |
| 点什么 | 批次行 → 执行识别 |
| 看什么 | 识别完成，跳转复核工作台，该档案标为**「人工复核」**（橙标） |

**这 3 分钟要讲透的三级识别**：

| 级别 | 表现 | 处理方式 |
|---|---|---|
| L1 直接识别（绿） | 页面清晰 + 校验通过 | 可批量确认 |
| L2 反推（黄底） | 看不清但能从别的字段推（金额从大写推、终止日从起租日+年限推） | 必须对照原件 |
| L3 不可识别（红底） | 推不出 | 必须手工录入 |

> 「为什么这份转人工复核？因为它**有涂改**。这是设计好的强制降级——涂改件一律送人工。」

---

## 3 · 人工复核（8–10 分钟，**演示重心**）

### 3.1 打开字段表（1 分钟）

| 项 | 内容 |
|---|---|
| 点什么 | 左侧点选该档案 |
| 看什么 | 右侧 27 个字段：级别标签 / AI 识别值 / **最终值（可改）** / 置信度 / 判定依据 |

**关键话术**：「注意这一行——年租金小写。AI 读出来 **4018.25**，但我们看『涂改字段』这一栏，系统自己标出来了：这个字段有涂改，涂改前内容是 **4018.25**。真正的值是大写那一栏——**叁仟玖佰玖拾捌元贰角伍分 = 3998.25**。所以系统按 3998.25 走，同时把整份转人工复核。」

> 这是真实教训：VLM 首读会给出涂改**前**的内容，所以涂改件必须强制复核。

### 3.2 改一个字段（1 分钟）

| 项 | 内容 |
|---|---|
| 点什么 | 改「联系电话」→ 回车（或点笔图标） |
| 看什么 | 提示「已改正」→ 刷新后值变了 |

**话术**：「所有字段都能改，不只是红色那几项。改动会写审计日志，记前后值、操作人、时间——**这就是可追溯**。」

### 3.3 批量确认的二次确认（2 分钟，**防乱放的兜底**）

| 项 | 内容 |
|---|---|
| 说什么 | 「自动通过不是点一下就过。哪怕 38 份一起批，也必须看这个弹窗。」 |
| 点什么 | 返回列表 → 勾选 2–3 份「自动通过」档案 → 批量确认 |
| 看什么 | 弹窗：份数 / 涉及批次 / 含人工复核档数 / 校验通过率 / **最低置信度 Top3 预警** |

**话术**：「评分规则是自动通过且对 +1、错 **−1**、人工复核 +0.5。所以系统必须让经办人**在确认前看到最不可靠的三项**——这就是那个 Top3 预警存在的理由。」

### 3.4 宗地台账下钻（2 分钟）

| 项 | 内容 |
|---|---|
| 点什么 | 宗地台账 → 点任意宗地键（如 `LX-001`） |
| 看什么 | 抽屉：宗地信息 + **合同链**（多份合同按时间排）+ **逐年应缴/实缴/欠缴** + 缴费归集 + 减免登记 |

**话术**：「一宗一档。这一宗有几份合同、每年该缴多少、实缴多少、欠哪几年，全在一页。**欠缴 = 各年应缴和 − 实缴和**，一分不多一分不少。」

**如果评委问『为什么 2016 年这一年要算两份合同』**：
> 「因为这两份合同**期限重叠**。问题清单里已经标了『存疑待确认』，写明暂按『旧合同自新合同起始日前终止』计算——也就是重叠段只算新合同，并且给出了另一种算法的差额。**这属于要主管部门书面确认的，系统不替你拍板，但把账算清楚、把差额摆出来。**」

---

## 4 · 更新台账/清单/催缴对象 + 展示（3 分钟）

| 项 | 内容 |
|---|---|
| 点什么 | ① 合同治理 → 问题清单（筛「存疑待确认」）② 收缴管理 → 欠缴看板 → 勾选 → 生成催缴通知书 ③ 统计报表 → 税务推送 → 生成 |
| 看什么 | ① 13 类问题（严格 13 类，不自创）② 催缴单生成成功（短信标注模拟发送）③ 推送单覆盖 N 宗地 |

**话术**：「问题清单只有 13 类，这是硬约束——**不许自创类型**，否则三个月后没人能统计。催缴对象取登记现权利人，查不到才取最新承租人；电话优先用登记的。税务推送单字段对齐他们给的模板。」

**可选的『存疑怎么处理』一问**：
> 「按这个按钮：问题清单 → 消解。前提是拿到主管部门书面确认。点了之后问题关闭、留痕，重算按确认的算法走。」

---

## 5 · 撤回并重导（3–5 分钟，**评委指定动作**）

| 项 | 内容 |
|---|---|
| 说什么 | 「现在按评委要求，把刚才那批**撤回**。撤回不是删一条记录，是**按批次整体回滚 + 级联重算**——不会留下半截数据让账对不上。」 |
| 点什么 | 批次导入 → 该批次行 → 撤回 → 确认 |
| 看什么 | 批次状态变 `rolled_back`；该档案从复核列表消失；宗地台账数字**回到撤回前**（级联重算） |
| 再点什么 | 重新新建批次 → 再次上传同一批文件 → 识别 → 复核 → 确认 |
| 看什么 | 全流程可重复执行，结果一致 |

**收尾话术**：「撤回重导走完，用的是同一套规则、同一份标准答案，所以数字回来跟第一次一模一样——**可复现，才敢现场让评委点。**」

---

## 6 · 收尾（1 分钟）

| 项 | 内容 |
|---|---|
| 说什么 | 「最后回到三个数：**核算全对**（30/30 宗地、618/618 年度，盲测 4/4 + 92/92）；**人力从 26 人天压到约 2 人 5.5 天**（76% 批量确认 + 24% 逐项复核）；**每个数字都能追来源**（输入快照 + 公式 + 口径版本落 `rent_calc_trace`，改字段留审计日志）。」 |
| 点什么 | 系统管理 → 审计日志（展示刚才所有操作都有记录） |
